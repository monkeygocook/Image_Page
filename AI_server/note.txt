NOTE: สัญญาการเชื่อมต่อระหว่าง Backend กับ AI Server
==================================================
เขียนจากโค้ดจริงใน AI_server\main.py และ AI_server\services\*.py

ลำดับการทำงาน:  ผู้ใช้ -> Frontend -> Backend -> AI Server -> (ผลลัพธ์กลับทางเดิม) -> ผู้ใช้

*** AI Server ไม่รู้จัก login/token/ผู้ใช้เลย ***
Backend ต้องตรวจสอบสิทธิ์, จำกัดขนาด/ชนิดไฟล์ และจัดการ error ให้ผู้ใช้เอง
แล้วค่อยส่งต่อมาที่ AI Server เฉพาะข้อมูลที่ต้องใช้ตามด้านล่าง


------------------------------------------------------------
0. ข้อมูลทั่วไป
------------------------------------------------------------
- Base URL (dev)  : http://127.0.0.1:8000        (ต่างจาก backend/API_SPEC.md ที่ใช้พอร์ต 7860)
- วิธีรัน         : python -m uvicorn main:app --reload     (ใช้ Python 3.12)
- ไม่มี prefix /api/v1 และไม่มี Authorization header
- ลองยิงด้วยมือได้ที่  http://127.0.0.1:8000/docs  (หน้า Swagger)

รูปแบบการส่ง:
- endpoint ที่รับรูป  -> multipart/form-data  (ชื่อ field ตามที่ระบุด้านล่างเป๊ะๆ)
- endpoint /generate  -> application/json

รูปแบบผลลัพธ์เมื่อสำเร็จ (HTTP 200):
- ได้ "ไฟล์รูปตรงๆ" (binary) ไม่ใช่ JSON  Content-Type: image/png
- Backend ต้องอ่าน response เป็น bytes แล้วส่งต่อให้ Frontend
  (หรือเซฟเป็นไฟล์แล้วส่ง URL ก็ได้ ตามที่ Backend ออกแบบ)

ข้อควรระวัง: ถ้าส่งค่าที่ทำให้ "ไม่ต้องประมวลผลอะไร" AI Server จะคืน "ไฟล์เดิมที่ส่งมา"
  ไม่ใช่ PNG ที่แปลงใหม่ (เช่น blur_amount=0, ไม่พบใบหน้า, mask ว่าง)
  ดังนั้นไฟล์ที่ได้อาจเป็น JPEG/WEBP ตามไฟล์ต้นฉบับ แม้ header จะบอก image/png
  Backend ไม่ควรสมมติว่าเป็น PNG เสมอ

1. GET /health
------------------------------------------------------------
ใช้เช็กว่า AI Server ยังทำงานอยู่
ส่ง    : -
คืน    : {"status": "ok"}   (JSON)


------------------------------------------------------------
2. POST /remove-background   (ลบพื้นหลัง)
------------------------------------------------------------
ส่ง (multipart/form-data):
  image   ไฟล์รูป (ต้องมี)
คืน (200): PNG พื้นหลังโปร่งใส
Error (422): INVALID_IMAGE  ไฟล์เสีย/ไม่ใช่รูป
          -> Backend ควรตรวจชนิด/ขนาดไฟล์ก่อนส่งมาด้วย


------------------------------------------------------------
3. POST /blur   (เบลอภาพ)
------------------------------------------------------------
ส่ง (multipart/form-data):
  image        ไฟล์รูป (ต้องมี)
  blur_type    ข้อความ: "gaussian" | "background" | "face"    (ค่าเริ่มต้น "gaussian")
                 gaussian   = เบลอทั้งภาพ
                 background = คนหรือวัตถุหลักคมชัด เบลอเฉพาะพื้นหลัง
                 face       = เบลอเฉพาะใบหน้าที่ตรวจเจอ
  blur_amount  จำนวนเต็ม 0-100 (ค่าเริ่มต้น 40)  0 = ไม่เบลอ, 100 = เบลอสุด
คืน (200): PNG
  - blur_amount = 0            -> คืนไฟล์เดิม ไม่ถูกแก้
  - blur_type = face แล้วไม่พบใบหน้า -> คืนไฟล์เดิม ไม่ถูกแก้ (ไม่ถือเป็น error)
Error:
  422  blur_type ไม่ถูกต้อง   -> detail.error.code = "INVALID_BLUR_TYPE"
  422  blur_amount นอกช่วง   -> detail.error.code = "INVALID_BLUR_AMOUNT"
  422  ไฟล์เสีย/ไม่ใช่รูป    -> detail.error.code = "INVALID_IMAGE"


------------------------------------------------------------
4. POST /filter   (ฟิลเตอร์ 10 แบบ ปรับความเข้มได้)
------------------------------------------------------------
ส่ง (multipart/form-data):
  image        ไฟล์รูป (ต้องมี)
  filter_name  ข้อความ (ค่าเริ่มต้น "grayscale") เลือกได้ 1 ใน 10:
                 grayscale, sepia, warm, cool, vivid,
                 vintage, cinematic, sharpen, sketch, cartoon
  intensity    จำนวนเต็ม -100 ถึง 100 (ค่าเริ่มต้น 100)
                 +100 = ใช้ฟิลเตอร์เต็มที่
                   0  = ไม่เปลี่ยนภาพ (ได้ภาพเดิม)
                 -100 = ผลตรงข้ามของฟิลเตอร์เต็มที่ (เช่น cool -100 = ออกโทนอุ่น)
คืน (200): PNG
Error (422):
  INVALID_FILTER     filter_name ไม่อยู่ในรายการ
  INVALID_INTENSITY  intensity นอกช่วง -100..100
  INVALID_IMAGE      ไฟล์เสีย/ไม่ใช่รูป


------------------------------------------------------------
4.1 POST /adjust   (ปรับภาพ 5 สไลเดอร์)
------------------------------------------------------------
ส่ง (multipart/form-data):
  image        ไฟล์รูป (ต้องมี)
  brightness   ความสว่าง          จำนวนเต็ม -100..100 (ค่าเริ่มต้น 0)
  contrast     คอนทราสต์          จำนวนเต็ม -100..100 (ค่าเริ่มต้น 0)
  saturation   ความอิ่มสี         จำนวนเต็ม -100..100 (ค่าเริ่มต้น 0)
  temperature  อุณหภูมิสี (- เย็น / + อุ่น)  จำนวนเต็ม -100..100 (ค่าเริ่มต้น 0)
  vignette     ขอบมืด (+ มืดลง / - ขอบสว่าง)  จำนวนเต็ม -100..100 (ค่าเริ่มต้น 0)
  ทุกค่า 0 = ไม่เปลี่ยนภาพ  ส่งเฉพาะตัวที่ผู้ใช้ปรับได้ ตัวที่ไม่ส่งถือเป็น 0
คืน (200): PNG
Error (422):
  INVALID_ADJUST_REQUEST  ค่านอกช่วง -100..100 หรือไฟล์เสีย/ไม่ใช่รูป


------------------------------------------------------------
5. POST /generate   (สร้างภาพจากข้อความ)
------------------------------------------------------------
** AI Server ไม่ได้สร้างภาพเอง แต่ส่งต่อไป Stable Diffusion Forge
   ที่ http://127.0.0.1:7860 (เปลี่ยนได้ด้วย environment variable FORGE_URL)
   ต้องเปิด Forge ด้วยแฟล็ก --api ค้างไว้ก่อน ไม่งั้นจะใช้ไม่ได้ **

ส่ง (application/json):
  {
    "prompt": "ข้อความอธิบายภาพ",        (ต้องมี)
    "negative_prompt": "",                 (ไม่บังคับ ค่าเริ่มต้นว่าง)
    "seed": -1                             (ไม่บังคับ จำนวนเต็ม  -1 = สุ่ม)
  }
คืน (200): PNG ภาพที่สร้างได้ (1 ภาพ)
  - ใช้เวลานาน (ตั้ง timeout ไว้ 300 วินาที) Backend ควรตั้ง timeout ให้นานพอ
    และให้ Frontend แสดงสถานะกำลังประมวลผล
Error:
  503  เชื่อมต่อ Forge ไม่ได้ หรือ Forge ตอบ error
       รูปแบบ: {"detail": "ข้อความภาษาไทยอธิบายสาเหตุ"}   (เป็น string ไม่ใช่ object)
  422  body ผิดรูปแบบ (เช่น ไม่มี prompt)  เป็นรูปแบบมาตรฐานของ FastAPI


------------------------------------------------------------
6. รูปแบบ Error ของ AI Server (สำหรับให้ Backend แปลงเป็น error ของตัวเอง)
------------------------------------------------------------
ส่วนใหญ่จะได้ JSON หน้าตานี้ (ห่อด้วยคำว่า "detail" ของ FastAPI):

  {"detail": {"error": {"code": "INVALID_BLUR_TYPE", "message": "Unsupported blur_type: xxx"}}}

ข้อยกเว้น: /generate ตอบ 503 เป็น {"detail": "ข้อความ"}  และ 422 ที่ FastAPI สร้างเอง
(เช่น ขาด field) จะเป็น {"detail": [ ... รายการ ... ]}

แนะนำ: Backend ควรจับ HTTP status ทุกตัวที่ไม่ใช่ 200 แล้วแปลงเป็น error ของ Backend
(ตาม backend/API_SPEC.md) อย่าส่งข้อความ error ดิบของ AI Server ให้ผู้ใช้โดยตรง

ตารางสรุป:
  HTTP  เกิดเมื่อ                               Backend ควรทำ
  422   ค่าที่ส่งมาไม่ถูกต้อง / ไฟล์เสีย        แจ้งผู้ใช้ว่าข้อมูลหรือไฟล์ไม่ถูกต้อง (400/422)
  503   Forge ไม่พร้อม (เฉพาะ /generate)        แจ้งว่าบริการสร้างภาพยังไม่พร้อม (503)
  500   AI Server ขัดข้อง                       แจ้งว่าระบบขัดข้อง (500)
  เชื่อมต่อไม่ได้เลย  AI Server ไม่ได้รัน        แจ้งว่าระบบ AI ไม่พร้อม (503) และเช็ก /health


------------------------------------------------------------
7. สิ่งที่ Backend ต้องจัดการเอง (AI Server ไม่ทำให้)
------------------------------------------------------------
- ตรวจสิทธิ์ผู้ใช้ (token) และจำกัดการเรียกถี่เกินไป
- ตรวจชนิดไฟล์ (PNG/JPG/WEBP) และขนาดไฟล์ (เช่น ไม่เกิน 50 MB) ก่อนส่งมา
  (ในโค้ด AI Server ยังไม่มีการตรวจนี้ ตามที่ README ระบุว่ายังต้องทำต่อ)
- ตั้ง timeout ให้นานพอ โดยเฉพาะ /generate (สูงสุด 300 วินาที)
  และ /remove-background ครั้งแรก (ต้องโหลดโมเดล rembg)
- แปลงชื่อ field ให้ตรง: Frontend/API_SPEC ใช้ path และชื่อ field คนละแบบกับ AI Server
  ต้องแมปให้ตรงตามตารางข้างบน
